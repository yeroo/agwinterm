# P2 — stop lying to the caller

Batch **P2** of the parity programme in
[2026-09-03-parity-batches.md](2026-09-03-parity-batches.md). Closes items 5 (the `sidebar.width`
half), 6 and part of 11 of [agterm-parity.md](../agterm-parity.md), and the `session.new`

## Decision 1 is answered: `session.new` **refuses** an unknown workspace

The batches file lists this as a question for Boris (`2026-09-03-parity-batches.md:40`). Answering
**refuse**, for three reasons, all of them reversible only in the expensive direction:

- agliteterm already refuses, and the whole point of the parity programme is that one script works
  against both products. Two answers to the same call is the divergence we are here to remove.
- Every *other* workspace-taking verb in this file already refuses — `SessionToWorkspace`
  (`Program.ControlHost.cs:341`), `WorkspaceSelect` (`:390`), `WorkspaceDelete` (`:382`).
  `session.new` is the outlier, not the precedent.
- The conformance contract already states the principle in prose, for `workspace.select`:
  *"Workspaces resolve by index or name, and an unknown one is refused rather than silently acting on
  the active workspace"* (`tests/conformance/control-api.json:509`). We are making `session.new` obey
  a rule the shared floor already declares.

**This is a behaviour change to a shipped verb.** A caller that today passes a typo'd workspace and
gets a session in the active workspace will, after this, get `ok:false` and no session. That is the
intent — the batch exists because that caller believes something false — but it is the one item here
that can break a working script, so it is called out at the top rather than buried in a task.

If Boris wants the fallback kept, Task 5 is the only task to drop; the other four stand alone.

## Overview

Five items, one defect class: **a call that appears to succeed while doing something other than what
was asked.** This is the class #213 opened (`session.type` refusing a control byte instead of
silently sending it) and this batch closes the rest of it in the control API.

- **`--stdin` on `session type`** — there is no way to type text that contains a quote, a newline or a
  leading `--` today. The CLI joins argv with a single space (`Ctl/Program.cs:165`), so multiple
  spaces and argument boundaries are already lost, and the option splitter (`:45-56`) eats a
  positional that starts with `--`. Every one of those losses is silent. `--stdin` takes the bytes
  unmodified; **invalid UTF-8 is refused**, not replaced with U+FFFD, because a replacement character
  arriving in a shell is exactly the "succeeded, wrong content" failure this batch is about.
- **`--size-percent` is validated, not clamped** — today `-5`, `0`, `150` and `sixty` all produce a
  full-screen overlay with `ok:true`. Three separate silent coercions: the CLI drops an unparseable
  value (`Ctl/Program.cs:200`), `GetInt` defaults a non-number to 0 (`ControlServer.cs:1007`), and the
  host clamps (`Program.Sessions.cs:737`, `Program.ControlHost.cs:603`).
- **`session.restore` names the pane it pinned** — the reply is the constant `"pinned"`
  (`ControlServer.cs:285`), and the target resolution it goes through is *not* the one the other verbs
  use, so which pane got the pin is genuinely unpredictable from the caller's side. Worse,
  `AgentSkill.cs:71` tells agents the pin is readable in `tree --json` as `restoreCommands` and
  **`HandleTree` never emits that field**, so there is no read-back at all.
- **`sidebar.width`** — new verb: set and report the sidebar width, with the reply carrying the width
  *actually in effect*. It also closes the same class one level up: `sidebar` answers `Ok("sidebar")`
  for an op it did not understand (`ControlServer.cs:254` plus the fall-through switch at
  `Program.Sessions.cs:1575`), which is how `sidebar on` sits in the conformance file passing while
  doing nothing at all.
- **`session.new` refuses an unknown workspace** — see the decision above.
- **`session.new` with *no* workspace argument lands in the caller's own workspace** — added
  2026-09-04 after Boris reported sessions still appearing in random workspaces on his work laptop,
  in **agliteterm**. Same defect class, other half: the refusal above only covers a workspace the
  caller *named*. With no argument at all — what a plain `session new` from an agent does — both
  products fall through to "the active workspace", and *active* is a global the UI moves constantly.
  In lite `g_activeWs` is rewritten by selecting any session in the tree (`main.cpp:5816`), by
  clicking a workspace node (`:5822`), by the focus toggle (`:5275`), by `session.select` (`:6587`)
  and `session.split` (`:6630`), and by **`workspace.new` over the API** (`:6764`) — so one agent
  creating a workspace redirects every *other* agent's next `session new`. agwinterm has the same
  shape and reads `ActiveWorkspace()` **inside the deferred `Post`**
  (`Program.ControlHost.cs:262-269`), so its answer additionally depends on when the UI thread gets
  round to the lambda. Lite's own comment at `main.cpp:6755` already describes the symptom ("the
  active one moves every time a session is selected - so an agent creating several sessions
  scattered them wherever the user had last clicked"); it fixed only the explicit-argument half.

## Constraints

- **Do not touch `tests/conformance/control-api.json`.** It is the shared floor and agliteterm's CI
  checks its copy against it every build. The steps for this batch — a
  `session new --workspace no-such-workspace` error step, an overlay `--size-percent` step, a
  `sidebar width` step — land in a **small sibling PR after this one merges and before the release**,
  exactly as #223 followed #221. A named non-goal, not an oversight.
- **`sidebar on` must keep passing.** The conformance file's `sidebar on` step (`:351-358`) hits an op
  `SidebarOpInternal` does not handle and passes only because the verb answers `Ok` unconditionally.
  Task 4 makes unknown ops refuse, so **`on` / `off` must become real aliases of `show` / `hide`** in
  the same commit. Turning a green step red is a contract break even when the file itself is untouched.
- **Additive tree fields only.** `restoreCommands` is new on the wire; the conformance file's
  `window.state` note ("Extra fields are allowed; these must be present") is the standard. Do not
  remove or rename an existing field.
- **No pty-host protocol change**, and no restore-format change — `PaneState.RestoreCommand` already
  exists and is already persisted. P3 owns the next format change.
- Follow the existing reply envelope: `Ok` / `OkRaw` / `Err`, and `RefusePrefix` from the host.
- Refusal logic belongs in `Agwinterm.Pty` where `FakeSessionHost` can exercise it, wherever the
  choice exists. `OverlayTargetRefusal` sits in the untested Win32 assembly and that is why #213's
  pane-widening refusal has no unit test; do not add to that pile.
- Cross-cutting safety rules from `qa/product.md` apply in full: sandbox instance (`--pipe <name>`
  **and** `--app-id <sandbox>`), never `keybd_event` / `SendInput`, `PrintWindow` never
  `CopyFromScreen`, never the real user profile, never `--no-restore` against real data.

## Technical Details

- **Why refuse rather than clamp, twice.** Tasks 2 and 4 both had a "clamp but report it" option, and
  agterm's own wording for `sidebar.width` ("distinguishing a clamped request from an honoured one")
  invites it. One API should have one answer to "you asked for something outside the range", and a
  refusal is the answer that cannot be ignored: a reported clamp still leaves an `ok:true` for a script
  that checks nothing but the exit code. The reply still reports the width in effect, which is what
  makes a *legitimate* difference — the chrome's own minimum on a high-DPI monitor, say — visible
  without pretending the caller's number was honoured.
- **Why invalid UTF-8 must be caught client-side.** The control pipe is read with a `StreamReader` over
  `Encoding.UTF8` with the default replacement fallback (`ControlServer.cs:141`), and the request is
  JSON, which is defined over text. By the time bytes reach the server they are already valid UTF-16
  with U+FFFD substituted, and no server-side check can recover the difference. This is not a
  preference; the server cannot see the failure at all.
- **Why `restoreCommands` gets emitted rather than the doc corrected.** Both would be honest. Emitting
  it is what the batch is for: without a read-back, "which pane received the content" is answerable
  only in the instant of the call, and a caller reconnecting to a running app has no way to ask.
- **Why the id hoist in `session.new` matters beyond the refusal.** Returning an id before the work is
  posted means every failure inside that lambda is invisible to the caller — the unknown workspace is
  merely the one we know about. Hoisting the resolution does not fix the general case (the creation
  itself is still posted) and this batch does not claim to; it fixes the question that has a wrong
  answer today.
- **Why the caller's workspace, and not a stricter rule.** Three candidates were on the table:
  default to the caller's workspace, keep "active" but stop session-selection moving it, or refuse a
  bare `session new` outright. The second does not actually fix it — two agents in one workspace
  still share one global, and the user's own clicking still steers it — and the third breaks every
  existing script, including the hub tooling under `C:\Users\boris\AI`. The caller's pane is the
  only answer that is both non-arbitrary and free: the identity is already in the environment of
  every pane the terminal starts, and every other verb already reads it.
- **`quick type` is deliberately not a verb.** agterm has one because its quick terminal is not
  addressable any other way; ours is a pane with an id (`Program.Sessions.cs:703`, `"quick:" + …`) that
  `FindPaneBy` already reaches. A second spelling of `session type` would cost a contract step, a lite
  mirror and a divergence risk, and buy nothing.
